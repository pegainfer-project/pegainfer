## Execution and evidence contract

The supported versions are campaign spec/compiled campaign 8, request plan 5, measurement 4, execution index 2, normalized campaign 5 and fit 3. Prepared references use their own kind/schema 1; runtime profile 3 and calibration manifest 2 are unchanged. Recompile an experiment after changing its measurement contract; the current execution path does not read old artifacts or generate old-format rows for downstream tools awaiting migration.

Compilation checks the explicitly named bench executable's version and help digest, local tokenizer files, observer implementation/configuration and pinned Python dependencies. Runtime checks the frozen inputs again. The Linux `/usr/bin/setpriv` launcher is also pinned by path, version/help and binary digest; it only sets the parent-death signal before executing bench and does not change UID/GID or privileges. There is no PATH fallback or runtime seed/shape override. Install the versions in `scripts/sim-calibrate/requirements-evidence-proxy.txt` in the environment used for compilation and execution.

For every phase/repeat, the driver invokes original bench with exactly C prompts and concurrency C, rate infinity, internal warmups/readiness generation disabled. It waits for the bench process, upstream requests and evidence writer to drain before starting another batch. A fixed batch never replenishes completed requests. Readiness uses `/v1/models` without requiring `/health` or generating a completion.

The driver registers bench's generated index set before sending. Actual `x-request-id` headers bind requests to plan keys; arrival order, completion order and digest uniqueness are not identity substitutes. The proxy reserves an identity before any await that could dispatch upstream. Duplicate or ambiguous identities invalidate the attempt and are never forwarded a second time. Original bench's internal retry is not configurable: the recorded policy is at-most-once **upstream forwarding**, not a claim that client retries are disabled.

Formal timestamps use the proxy's monotonic clock:

- TTFT ends at the first event containing non-empty **output token IDs**, including IDs with empty text. Prompt IDs, role, usage and finish-only events do not qualify.
- First text latency is separate; a space/newline qualifies, and no text yields null. Entirely missing output IDs yields unsupported token timing; text never substitutes for token TTFT. Partial IDs have the explicitly accepted false-success limitation documented in finding 1.
- Multi-token events retain their actual read timestamp and token count. An interval uses its right event's token count; the first event's tokens are excluded from the interval denominator. Request TPOT is diagnostic; `steady_state.py` owns the common-window fit source.
- E2E ends at upstream EOF, including usage/stream tail. HTTP, finish, DONE, EOF, parser failures and downstream failures are retained independently. Truncation, count disagreement and explicit error events cannot be sealed successfully.

Raw upstream reads are recorded before parsing. UTF-8/SSE framing may cross reads; an event is timestamped by the read containing its closing boundary. Multiple events in one read can have the same timestamp. No synthetic per-token timestamps are inserted. Actual request bytes, normalized body and prompt-ID digests are retained; model routing is excluded only from the normalized workload body.

A trailing CR retains its own read timestamp while awaiting an optional LF. If LF follows, the boundary uses that LF's read; otherwise the saved CR time applies, including at EOF. Waiting for the next byte no longer assigns a later read time to a complete CR-only event.

The observer source map freezes 24 execution inputs, including the fitter and C7 replay/report/acceptance implementations. Plans require the complete source set and valid digests. Runtime rechecks it before each attempt or sealed reuse, after collection and before sealing; measurements bind the same observer digest as their execution entry. Reports also enforce the frozen report and validation-normalizer sources. A mismatch requires recompilation and new acquisition in a new artifact root. Historical evidence is never relabelled after source changes.

The proxy uses a bounded evidence queue, limits open files and flushes/fsyncs before each batch transition and final sealing. Queue overflow, storage failure or dropped evidence fails the attempt. The original bench's unconditional optional `/metrics` reads are recorded and answered locally with 404; they are not forwarded to target or used as formal metrics. This behavior is part of observer identity.

## Artifacts, failure and profile binding

`artifact_index.json` remains the immutable compiler index. Runtime state is in `execution_index.json`; raw files live under `raw/<variant>/<cell_id>/attempt-N/`. Measurements bind the raw index and workload evidence. An execution lock prevents concurrent drivers from replacing checkpoints. Failed/interrupted attempts retain their bytes; recovery allocates a new directory and reruns the complete phase sequence. Sealed results are skipped only after verifying their indexed evidence and measurement digests.

`campaign.py run` calls `plan_driver.run_campaign`, which opens `artifacts.ExecutionStore`. The store writes `execution_index.json` atomically when an attempt begins and updates it when the attempt finishes; it is not a bench/proxy output or a compilation artifact.

Timeout/cancellation kills and reaps the owned bench process group; parent-death signaling also terminates bench if the driver is killed directly, and the interrupted attempt is recovered in a new directory; stdout/stderr are written during execution and retained on failure. The driver owns the bench and proxy lifecycle. `campaign.py run` keeps existing servers caller-owned; the full-stage `execute` entry owns the profile servers it launches, while the existing target remains caller-owned.

For profile-backed zero_cost/sim, supply `--server-pid VARIANT=PID`. C2 verifies the local process's profile argument, profile/calibration digests, model, scheduler and start time. Driver and server must share a network namespace. The configured endpoint must explicitly use IPv4 `127.0.0.1`; every matching listener at that address or `0.0.0.0` must belong to the PID. Same-port IPv6 listeners are conservatively rejected because IPv6/dual-stack attestation is outside this scope. Bindings record namespace and listener address/port/inode, and are rechecked before each attempt or sealed reuse, after collection and before sealing. `localhost` is rejected with a request to use the explicit IPv4 address; target endpoints retain their existing rules. The zero_cost attempt pins its cell and immutable preparation-list digest. The live profile must match that cell’s prepared profile/manifest bytes and runtime; the driver resolves and verifies the selection before each binding check. This binding requires Linux `/proc`; remote/cross-namespace profile attestation is not implemented. A pending fitted sim profile does not prevent compilation or target/zero-cost collection.

Cold targets with caching enabled require an explicit reset lifecycle; a false/unavailable reset fails before generation. Turning caching off avoids that requirement. C8 connects cached text preparation, bootstrap/hit validation and recovery to the same driver. Cached target/zero_cost collection is supported; requesting a cached simulator runtime remains unsupported. The independent recorder/collector/artifact adapter and their old store are removed.

## Exact pairing and offline normalization (C3)

Normalize requires explicit `scope=train` or `scope=validation`. Train selects every declared cold/decode/cached train cell and requires target/zero_cost. Validation selects every declared non-train cold/decode cell and requires all three roles; original split names remain in the observations. There is no arbitrary cell selector for a successful normalized scope. Empty scopes fail. Online cached validation remains explicitly unsupported, with the full campaign required-scope digest retained; the separate C9 offline surface report does not establish online cached acceptance.

`artifacts.execution_snapshot` reads the execution index under the driver's existing lock. `sealed_reference` pins the selected attempt number/path, plan, binding and measurement/workload/raw references. `read_sealed_attempt` checks indexed bytes and the same measurement links used at sealing. `normalize.verify_normalized_sources` later follows the pinned references, independently of the current execution index. Adding sim or other cells therefore does not invalidate an existing training source snapshot; changing a selected source file does. The original execution-index digest is an audit fact, not a requirement that the current index remain byte-identical.

`pairing.validate_attempt_evidence` checks registered transport IDs and request instances against the plan, replays original response bytes/read boundaries through the existing SSE parser, and checks conversion through the existing converter. Recorded commands are checked with the original bench adapter; proxy addresses, output locations and transport prefixes are execution metadata. Raw request JSON must agree with wire JSON and the frozen shape/sampling contract. Acquisition and offline pairing share `evidence_proxy.validate_request_body`; the former duplicate instance method is removed.

Pairing compares prompt/token/normalized-body digests for each plan key across roles. It permits different roles to use different model routing and transport IDs, and permits different keys to have identical content when their mappings are explicit. It does not require entire workload-evidence or wire-body digests to be equal across roles. All logical requests, including warmup, must be valid; only measured requests become observations. Batch membership and completion-before-next-dispatch are checked within each role's monotonic clock. Different roles' absolute timestamps and dispatch skew are not equality constraints.

The normalizer validates saved acquisition identity and profile file bindings without contacting a live PID or comparing historical acquisition-source hashes with current local files. Live and offline checks share the static endpoint/listener contract in `probe.py`: the saved endpoint must match the configured IPv4 loopback address/port, with matching IPv4 loopback or wildcard listeners. Live socket ownership remains the driver's responsibility. Its own implementation source hashes are recorded separately. New acquisition still enforces the complete current source map and requires recompilation after source changes. This is file integrity and semantic consistency, not an externally signed attestation against rewriting an entire digest chain.

Acquisition and offline pairing also share the existing reset lifecycle and success predicate. Only target with cache enabled and a reset lifecycle requires indexed `reset.json`: before the first batch for `cell`, or every warmup/measured batch for `repeat`. A cold target with cache enabled requires an explicit lifecycle. HTTP 200 plus JSON `true` or `{"success": true}` proves the receipt's success; missing, false or unsuccessful receipts fail validation. Cache-off targets and simulator roles retain their existing behavior. The cold receipt has no timestamp and does not independently establish reset ordering; cached recovery groups separately bind monotonic restoration completion and bootstrap dispatch.

Output is `kind=normalized_campaign`, schema 5, with scope and selected-source digests, expected/matched/observed counts, failures, original per-role measurements/events and fit policy. Validation still requires complete target/zero_cost/sim pairing and remains non-fit-ready. Train cells also include the prepared reference and recomputed residual/effective values; only a complete qualified train scope has `fit_ready=true`. Fit schema 3 consumes that artifact after full evidence verification; target-only, incomplete, old-schema and tampered artifacts are rejected. Output publishing remains exclusive/idempotent and refuses source artifact paths.

`normalize.verify_normalized` validates a complete succeeded document, including observations, cell/top-level counts, fit readiness and the normalizer source-map digest. It compares saved results with the canonical results returned by source verification, using the same cell/observation/document assembly as normalization. `verify_normalized_sources` remains scoped to the pinned sources. Successful output publishing calls the complete validator before writing; later consumers should use it when trusting normalized results.

The observed zero-cost C=4/output-32 C2 repeats have no common decode window: 32 generation events per request were received in one upstream read, so first/last generation observations coincide. C3 preserves this evidence and can pair it. C4 rejects it before sealing in new campaigns; C5 must supply a qualified interval reference; diagnostic request TPOT=0 does not establish zero frontend cost. Partial token IDs retain the explicitly accepted completeness limitation.

## Complete decode windows and target statistics (C4)

Decode matrices now declare only `concurrency × num_ctx`, where `num_ctx` is the initial **total** context across the fixed batch. Each request receives exactly `num_ctx / concurrency` prompt tokens; non-divisible coordinates and per-request context ceiling violations fail compilation. The additive and surface candidates share these cells. Retired `context_tokens`, `surface_requests`, `surface_kv_tokens` and free-form `steady_state` fields are rejected. At C4 this introduced campaign/compiled schema 6, plan 3 and normalized 3; C5 advances those to 7/4/4 for reference policies, split and qualified training. Execution index remains 2 and raw measurement remains 3.

The checked-in fixture declares 12 train coordinates, B={1,2,4} × num_ctx={256,1024,3072,6144}, plus 11 `sealed_test` coordinates. Each uses warmup=1, measured=2 and per-request output=8. Held-out coordinates are B={1,2,4} × num_ctx={1536,4096}, B=3 at num_ctx={1536,3072,4608}, and B={1,2} at num_ctx=512. This is one point set for both numerical candidates, with no duplicate collection by fit family. Output=16 is accepted only as another frozen plan; the driver does not change shape during execution.

For every complete batch, start=max(first output-ID timestamps), end=min(last output-ID timestamps). `steady_state.py` retains adjacent event intervals only when **both** endpoints are inside that inclusive window. Duration sums include zero-duration intervals, and the denominator sums each retained interval's right-event output token count. Multi-token events are kept intact, without timestamp interpolation. There is no 80% clipping or central-progress cross-check.

A measured batch qualifies when the common window is positive and every one of its B successful requests has at least one complete interval, positive total retained duration and positive token denominator. There is no additional interval-count, duration or jitter threshold. Request TPOT values have equal weight within a batch; measured batch means have equal weight across repeats. Raw request values, retained interval/token counts, distinct timestamps, window duration and repeat dispersion remain diagnostic. `repeat_count` counts batches, not B×repeats. Warmup retains all request/content/terminal checks but its window does not gate measured qualification or enter means/dispersion. Cold-prefill's paired TTFT median remains unchanged.

The driver writes `decode_statistics.json` after measurement conversion and before `ExecutionStore.finish`. It is a separate schema-1 `decode_window_statistics` artifact, with a canonical measurement digest; the selected attempt pins its byte reference. Raw indexes exclude derived files to avoid digest cycles. The reader still rejects unindexed files/symlinks and rechecks the statistic against the pinned measurement. Failed measured qualification leaves raw evidence and reasons in a failed attempt; the next explicit run creates a new directory and reruns the full plan. Successful sealed reuse revalidates statistics. A burst-read zero-cost reference can therefore fail this gate even when its requests completed; that does not determine target output length.

`target_statistics.py` reuses `pairing.load_role`, `read_sealed_attempt` and `pairing.validate_attempt_evidence`. It selects every declared train decode target, freezes selected attempts and its implementation source map, and publishes schema-1 `kind=train_target_statistics`. `read_target_statistics`/`verify_target_statistics` recompute pinned results without consulting later execution state or a live service. This distinct artifact succeeds without zero_cost, while complete train normalization still requires target/zero_cost and validation still requires all three roles. Target-only statistics remain `fit_ready=false`; C5 consumes them for reference preparation and requires qualified paired subtraction before formal fitting. Numerical NNLS/bilinear helpers already share the hierarchical mean; the retired whole-request/stream-chunk decode fallback and pooled-row median are removed. Unreplaced cached and replay/report domain logic remains until C8/C7 respectively.

## Target-first references and paired training (C5)

Compilation freezes `reference_policy` and split into each cold/decode plan. It no longer creates a global `profiles/zero_cost/` control or accepts a supplied zero_cost profile. After every supported train target is sealed, `campaign.py prepare-reference` validates those exact attempts. Decode also verifies the independent target-statistics artifact; cold-only campaigns need no decode statistics and support output=1.

The immutable `references/preparation.json` pins compiler bytes, selected target attempts, embedded decode statistics and generator sources. Files live under `references/<preparation_id>/<cell_id>/{manifest,profile}.json`; the selection is published last. Identical preparation is idempotent. Compiler plans/index and raw evidence are never rewritten. Non-training cells receive zero-control diagnostic references without consuming held-out targets; they are not used to choose training parameters or establish fitted coverage.

For each train decode cell, delta is its target request→batch→repeat mean in milliseconds, rounded to integer microseconds. Both requested and encoded values are saved. The reference is functional: prefill=0, decode=the constant encoded interval, mixed=composition_additive with intercept 0. Runtime evaluates decode only when a step contains decode work, once per step regardless of B; broad known-reference coverage includes admissions and draining shapes. Each profile is loaded by a new caller-owned process before collection. There is no profile hot editing or second collector.

For each measured plan key, decode uses `residual = reference_window_TPOT - encoded_delta_ms` and `effective = target_window_TPOT - residual`. Cold uses paired `target_TTFT - reference_TTFT`, followed by the repeat median. C>1 TTFT is excluded from fitting. Normalization verifies both roles’ evidence and windows, actual reference bytes/interval and target lineage, then retains signed request values, batch/repeat means, min/max/stddev/MAD diagnostics and the final representative. Negative residual/effective values are retained. Decode requires a finite cell mean >0; cold requires a finite paired median >=0. An invalid cell blocks the complete train fit. Variation alone adds no rejection threshold, clipping or sample filtering.

The fitter revalidates the complete normalized artifact before extracting samples. Cold piecewise, decode additive and decode surface consume the paired effective values; both decode candidates share the hierarchical means. Fit schema 2 records the normalized digest, pinned training sources and fitter sources. A declared candidate failure makes the fit invalid. No sim/held-out acquisition or final report is needed for numerical training fit. C6 still owns selecting/materializing the fitted profile; C7 owns held-out report migration.

The artifact layout keeps compiled and acquisition evidence in place, and adds a separate immutable reference branch:

```text

  references/<preparation_id>/<cell_id>/manifest.json
  references/<preparation_id>/<cell_id>/profile.json
  raw/<variant>/<cell_id>/attempt-N/...
```

Target-statistics, normalized and fit output paths remain caller-selected; they are distinct derived artifacts. Reference selection and actual profile/process binding are pinned in each zero_cost attempt. Raw measurements and decode-statistics sidecars keep their existing formats.

The replaced `zero_cost_bundle`, compile-time unique control digest/path assumptions, schema-1 cold/decode extraction and temporary empty-decode fit barrier are removed. Shared scope/role readers moved to `pairing.py`; target statistics no longer imports the high-level normalizer. Cached domain helpers/collectors and legacy replay/report rules remain at their documented C8/C7 boundaries.

## Fitted profile lifecycle (C6)

`profile.py` consumes the current compiler bundle plus explicit normalized and fit artifact paths. It has no report input, implicit artifact glob, characterization mode or validation-error selection. Complete qualified train evidence remains mandatory. `fit.verify_fit` runs the existing numerical fitter against the pinned normalized input, including its production source verification, and compares the whole saved fit. Rehashing an edited candidate or normalized value cannot establish eligibility. Normalizer sources must match the frozen acquisition source map; fit/materializer implementation digests are retained separately.

C6 fixes selection to `cold_prefill_piecewise_linear` and `decode_2d_surface`; additive remains a numerical diagnostic and is never a runtime fallback. The full surface is converted from milliseconds to integer microseconds in request-major order. Axes must be strictly increasing, integer, dimensionally complete and representable by the Rust contract. No reference interval or baseline is added a second time. ## C2 audit findings (2026-10-15)

The following descriptions preserve the original reproductions. Findings 2—4 are now repaired as documented above; finding 1 is deliberately unchanged.

1. **Accepted known risk — partial output-ID streams can seal incorrect metrics; no fix this round.** Partial means some generated SSE events lack IDs; one event carrying only its own incremental IDs is normal. `convert_evidence` filters events to those with IDs and treats any nonempty filtered sequence as valid. With `ignore_eos=false`, no usage, an initial text-only output and a later ID-bearing output, the actual-bench integration sealed `succeeded/token_timing_valid=true`: the controlled endpoint was configured to emit 2 tokens, but 1 was recorded; first text was 14.827 ms and TTFT was 76.000 ms. The missing initial output can also distort TPOT. This was fault injection, not an observed normal vLLM/PegaInfer response; the prior 54-row three-role smoke did not show this pattern and does not establish a general frequency. The user accepts the risk and requests documentation only: no new completeness policy, fallback or automatic retry is planned for this case.
2. **P1 — PID binding matches only a port, not the endpoint address.** `profile_binding` accepts a PID listening on `127.0.0.2:P` for an endpoint at `127.0.0.1:P`. A full original-bench run against a separate controlled HTTP server at the latter address sealed as zero_cost while the attested PID served no HTTP. Verify address family and reachable local address plus port/socket ownership (including wildcard/localhost semantics), not port alone.
3. **P2 — The formal conversion/execution implementation is not frozen.** Observer source identity covers proxy, parser and requirements only. Changing the converter's first-text classifier to ignore whitespace changed its code/metric semantics but left observer identity unchanged. Runtime does not validate a converter/driver/adapter source identity; the compiler provenance source list also omits those modules. Bind the complete acquisition/conversion implementation and validate it on execution so different role runs cannot silently use different metric logic under one campaign identity.
4. **P2 — A complete CR-only SSE event can receive the next read's timestamp.** When a read ends with the closing CR of `\r\r`, the parser waits for the next byte and classifies the already-complete event with the later read timestamp. The parser reproduction delayed an event from 100 ns to 1,000,000,100 ns. Consume legal CR line endings with pending-LF handling, or preserve the closing boundary's original read timestamp; keep byte bounds auditable.
